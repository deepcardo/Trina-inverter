# ADR-001: 采用纯前端 + Vite 构建的渐进式架构

## 状态

已采纳 (2026-07-26)

## 背景

天合逆变器智能选型系统最初实现为一个单文件 HTML 应用，数据（逆变器配置表、线缆规格）、样式、业务逻辑全部耦合在 `index.html` 中。随着业务扩展（新增 780~785W 组件系列、湖南专用配置），单文件模式导致以下问题：

1. **修改 DB 非常麻烦**：每次更新逆变器配置需在 67KB 的 HTML 中定位并修改硬编码数据
2. **缺乏自动化**：Excel 数据源更新后，需手动同步到 HTML
3. **无构建步骤**：无法使用模块化、代码压缩、类型检查等现代前端工具

用户为单人维护团队，系统部署在 GitHub Pages，不接受引入后端服务。

## 决策

采用纯前端架构，引入 Vite 构建系统，具体包含：

1. **保持纯前端**：不引入任何后端服务，数据文件通过 HTTP 静态加载
2. **Vite 构建**：使用 Vite 进行开发服务器、模块打包、生产构建
3. **GitHub Pages 部署**：构建产物部署到 GitHub Pages，利用 GitHub Actions 实现自动部署
4. **渐进式迁移**：分阶段将单文件拆分为模块化结构，每阶段保持功能不变

## 理由

- **维护成本最低**：单人维护场景下，纯前端 + 静态托管的运维负担最小
- **GitHub Pages 原生支持**：原生支持静态网站，与 Vite 构建产物完美配合
- **渐进式风险可控**：每步拆分后验证功能回归，不影响线上服务
- **Vite 零配置启动**：无需复杂配置，`npm create vite` 即可开始
- **性能足够**：日活几十人的场景下，纯前端性能绰绰有余

## 被拒绝的方案

1. **引入后端（Node.js/Python）**：增加服务器维护、数据安全、成本负担，与用户意愿不符
2. **使用 React/Vue/Angular 框架**：对单人维护团队引入额外的学习成本和构建复杂度，当前功能用原生 JS 即可
3. **保持单文件不变**：随着组件型号增多，维护成本将持续上升，最终不可控

## 影响

- 开发流程变为 `npm run dev`（开发）→ `npm run build`（构建）→ 自动部署
- 需要配置 GitHub Actions 或手动运行 `npm run build` 后推送到 gh-pages 分支
- 旧版打开的本地 HTML 文件方式不再适用，需通过 `npm run dev` 或访问部署 URL
- 代码拆分后，逻辑更清晰，新人接手成本降低
