# ADR-002: 数据文件与代码分离策略

## 状态

已采纳 (2026-07-26)

## 背景

当前系统中存在多种数据，其存储方式不一致：

- **区域容配比数据**：独立在 `region-data.js` 中，已与代码分离
- **逆变器配置表（DB）**：硬编码在 `index.html` 的 `<script>` 标签中
- **湖南专用配置（HUNAN_DB）**：硬编码在 `index.html` 中
- **张家界专项配置（ZHANGJIAJIE_DB）**：硬编码在 `index.html` 中
- **线缆规格表（CABLE_THRESHOLDS）**：硬编码在 `index.html` 中

这种不一致导致：
1. 每次修改配置需在 67KB HTML 中搜索定位
2. 新增组件系列需在 HTML 中间插入代码，容易引发语法错误
3. 数据无法独立验证和测试

## 决策

将所有数据从 `index.html` 中分离到 `src/js/data/` 目录下的独立 JS 文件，统一为 ES Module 格式：

```
src/js/data/
├── region-data.js    ← 已有（保持现有格式或迁移到 ES Module）
├── inverters.js      ← 从 HTML 抽出的 DB（4个系列 × 3种容配比）
├── hunan.js          ← 从 HTML 抽出的 HUNAN_DB + ZHANGJIAJIE_DB
├── cables.js         ← 从 HTML 抽出的 CABLE_THRESHOLDS
└── constants.js      ← 共享常量（DATA_SOURCE、系列名称枚举等）
```

每个数据文件遵循统一接口：

```javascript
// inverters.js 示例
export const INVERTER_DB = {
  NEG21_715: {
    "1.2倍(正常)": [
      { r: [10, 13], inv: "8", box: 25, power: 8 },
      // ...
    ],
    // ...
  },
  // ...
};

export const SERIES_NAMES = {
  NEG21_715: "NEG21(715W)",
  NEG21_730: "NEG21(730W)",
  NEG22_785: "NEG22(780~785W)",
  NEG22_800: "NEG22(800W)",
};
```

特殊地区配置按业务优先级内聚：

```javascript
// hunan.js
export const HUNAN_DB = { /* ... */ };
export const ZHANGJIAJIE_DB = { /* ... */ };

// 查找优先级：张家界 → 湖南 → 通用
```

## 理由

- **与 region-data.js 策略对齐**：保持项目内部一致性
- **ES Module 格式**：Vite 原生支持，可用 `import/export` 管理依赖
- **单一职责**：每个文件只负责一类数据，修改时定位精确
- **独立可测**：可编写单元测试直接验证每个数据文件的完整性
- **扩展友好**：新增组件系列只需在 `inverters.js` 追加一条记录，新增省份专项配置只需在对应文件添加

## 被拒绝的方案

1. **保持 HTML 内嵌**：当前痛点来源，拒绝
2. **JSON 文件 + fetch 加载**：增加异步加载复杂度，数据量不大无需延迟加载
3. **SQLite / IndexedDB**：对静态配置数据引入数据库过于复杂

## 影响

- HTML 体积从 67KB 降至约 5KB（纯视图 + 逻辑）
- 所有 JS 文件通过 Vite 打包为一个 Bundle，生产环境无额外网络请求
- 修改配置时只需编辑对应数据文件，无需翻阅整个 HTML
- 新增组件系列的工作流：编辑 `inverters.js` → `npm run build` → 部署
